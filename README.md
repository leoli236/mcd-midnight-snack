## 项目介绍

主角是加了一天班的程序员。22:47 下班，疲惫又焦虑，想靠夜宵换一点即时快感，
又担心长胖、担心明天。你要替他走完这一晚：**下班 → 路过 → 挑心情 / 点单 → 权衡 → 一口一口吃掉 → 事后的自我审判**。

它是一个**选择式叙事游戏**，不是效率工具。核心是两组数值的此消彼长：

- **可见数值**：精力 / 心情 / 焦虑 / 满足感 / 体重 / 今日热量
- **隐藏数值**：放纵度 × 接纳度 —— 这两条轴决定你最终拿到哪个结局

设计上最较真的一点：**体重按 `kcal ÷ 7700` 真实换算**。
所以吃下一整个巨无霸，体重只涨 0.067 kg —— 而结算页会告诉你，
"其中大部分是那杯饮料的水"。把焦虑翻译成一个真实但很小的数字，它就没那么吓人了。

### 四项核心交互

**1. 同一份可以点多份**
点卡片 +1，左上角显示 `×N`，右上角「−」减一份。每多一份音效升一个调、卡片弹跳一下。
连点会冒出「你的手比你的理智先做了决定」这类话 —— 点击本身就是这个游戏的情绪出口。

**2. 心情菜单：6 种心情，每种配好一套**

| 心情 | 搭配名 | 配什么 |
|---|---|---|
| 想被安慰 | 安抚补丁包 | 派 + 牛奶 |
| 报复性快乐 | 生产环境放纵套餐 | 汉堡 + 薯条 + 可乐 |
| 假装健康 | README 里写的那种吃法 | 苹果片 + 牛奶 |
| 纯粹嘴馋 | 无理由分支 | 鸡翅 + 薯条 |
| 加班续命 | 续命 hotfix | 牛奶 + 派 + 薯条 |
| 回到小时候 | 童年快乐包 | 派 + 薯条 + 苹果片 |

搭配用**正则**匹配你门店的菜单名，门店叫法不同也不会整组失效；这家店没有的心情自动置灰。
你自己乱点出来的组合，游戏也会给它起个名字 —— 「咸甜交替型人格」「赎罪券套餐」「深夜全量回归测试」。

**3. 点哪一块，就吃掉哪一块**

```
        第 1 / 3 份 · 巨无霸
     ·  ·  ▓▓▓▓▓▓  ·  ·        ← 顶上那片面包
     ·  ▓▓▓▓▓▓▓▓▓▓  ·           ← 生菜和酱
     ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓            ← 第一块牛肉饼
     ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓            ← 中间面包 + 又一层生菜
     ·  ▓▓▓▓▓▓▓▓▓▓  ·           ← 第二块牛肉饼
     ·  ·  ▓▓▓▓▓▓  ·  ·        ← 压在最底下那片面包

   刚刚吃掉：第一块牛肉饼        ← 点一下，这一层就消失
   还剩 3 口
   [ 放下，不吃了 ]  [ 整份吃完 ]
```

每份食物被切成 3–6 口（汉堡 6 口、薯条 3 口、可乐 4 口……），点哪一层就吃掉哪一层：
像素消失、掉碎屑、咀嚼音效，连点会出连击。

这里有一条贯穿全作的设计：**热量按你实际点掉的口数结算，点了不吃不计入**。
所以「放纵 vs 克制」不再是一道选择题，而是你手上的动作 ——
你可以点三份，吃一份半，然后把剩下的留在盒子里。**这不是失败，这是知道自己够了。**

**4. 真实菜单：三种接法**
`window.__MCD_MENU__` 注入 / 同目录 `menu.js` / 开始界面「📂 载入我的门店菜单」选 `data/menu.json`。
载入后心情菜单和卡片全部重建。每张卡片按麦当劳当前在售菜谱展示 6 个字段：

| 字段 | 来源 | 说明 |
|---|---|---|
| 菜品名称 | `query-meals` | 门店真实叫法，心情菜单用正则匹配，不会因为叫法不同而整组失效 |
| 分类 | `query-meals` | 「汉堡 / 小食 / 饮料 / 甜品…」，顶部可按分类筛选 |
| 价格 | `query-meals` | `currentPrice`，实时售价，购物车合计按份数累加 |
| 图片 | `query-meals` / `query-meal-detail` | 官方图片 URL；**加载失败自动回退到像素图**，离线也能玩 |
| 热量 / 蛋白 | `list-nutrition-foods` | 官方营养表，热量驱动体重（÷7700），蛋白一并展示 |
| 所需食材 | `query-meal-detail` | 官方配料（`selectedQuantity > 0` 的项），进食时还会提示「这一口里有：…」 |

配料带 <span style="color:red">\*</span> 的是**已知值、需人工核对**（`data/menu-verify.txt` 列了清单）——
接口未返回配料的品类，代码用公开配方兜底，并在 UI 与注释里都标了出来，不做"假装是实时数据"。

**5. 后厨：会失败，也会回滚**
订单进后厨后**逐份**制作，每份独立判定：做成 / 掉地上重做（10%）/ **卖完了（6%）**。
缺料时那一份会被**从订单里划掉**（钱不收、热量不计），并给你两个选择：

```
✕ 巨无霸  卖完了。最后一份被前面那个人拿走了。
          已经从订单里划掉了，钱不会收你的。
          [ 换一个 ]  [ 就这样吧 ]
```

- **换一个** → 状态机 `KITCHEN → PICK`，回到点单界面，**剩下的份数原样带回**，可以继续加
- **就这样吧** → 继续做下一份；如果整单都被划掉，走「空手回家」结局

失败不是死局，是流程的一部分。

### 音效：搞怪，但不刺耳

18 种**现场合成**的 8-bit 音效，覆盖每一个交互节点：

| 节点 | 音效 | 听感 |
|---|---|---|
| 点击 / 悬停 | `click` / `hover` | 短促方波「哒」，悬停更轻 |
| 加一份 | `add(n)` | 每多一份**升一个调**（470 + n×70 Hz），连点的爽感来自这里 |
| 减一份 | `remove` | 下滑音「噗」 |
| 选中心情 | `mood` | 三音上行琶音 |
| 下单 | `order` | 收银机 **ka-ching** |
| 开始制作 | `cookStart` | 噪声扫频 420→2200 Hz，油锅「嘶——」 |
| 制作中 | `tick` | 定时器滴答（320 ms 一次） |
| 制作成功 | `cookSuccess` | 上行两音「叮」 |
| 掉地上重做 | `cookFail` | **wah-wah** 下滑，故意滑稽 |
| 缺料 | `error` | 下行两音，短，不刺 |
| 出餐 | `serve` | 取餐台「叮咚」（880 + 660 Hz 正弦） |
| 咬一口 | `bite(n)` | 噪声 + 低频方波，连击越高越亮 |
| 喝饮料 | `gulp` | 两声吞咽 |
| **连续正确操作** | `combo(n)` | 连击 ≥3 触发，音高随连击递增 |
| 结算金币 | `coin` | 经典马里奥式两音 |
| 解锁成就 | `unlock` | 四音上行 |
| 结局 | `ending` | 温和下行收尾 |

**三重防爆音设计**（高频连点是最容易出爆音的场景）：

1. **总线压缩** —— 所有声音先过 `DynamicsCompressor`（threshold −18 dB / knee 12 / ratio 6），峰值被压住
2. **复音上限** —— 同时最多 10 个发声体（`MAX_VOICES`），超了直接丢弃，不排队堆积
3. **按名节流** —— 每种音效独立最小间隔（click 45 ms、bite 70 ms、error 200 ms…），
   连点 100 次实测并发只有 3 个发声体，不会叠成噪音

右上角有 **🔊 静音开关** 和 **音量滑杆**（0–100%，默认 60%）。设置存 `localStorage`，下次打开还在。

资源缺失时也做了降级：如果 `window.__MCD_SFX_BASE__` 指向的音效包下载失败（404 / 离线 / CORS），
自动 `sampleFail = true` 并**静默回退到合成音**，不报错、不静音。`?debug=1` 会在调试栏显示 `sfx=synth（资源缺失，已回退合成）`。

浏览器要求首次交互才能启动 `AudioContext`，所以在第一次 `pointerdown` 时才 `resume()` ——
这也意味着**页面刚打开时是安静的**，不会突然响一声吓到人。

### 完整闭环：每一步都有前置条件

整局由一个**显式状态机**驱动，12 个状态、22 条转移，每条转移都写明 `from / to / guard / effect`：

```
BOOT → TITLE → LEAVE → ROUTE → PICK ⇄ PICK → CONFIRM → KITCHEN → SERVE → EAT → REVIEW → BED → RESULT
                                        ↘ EXIT_EMPTY ↗          ↘（缺料）PICK
```

```js
ADD_ITEM: { from:['PICK'], to:'PICK',
  guard: p => p.item.status === 'on-sale' && (p.qty||0) < MAX_QTY }   // 售罄 / 单品上限 5 份
```

| 边界情况 | 处理 |
|---|---|
| 单品点超过 5 份 | 前置条件拦下，提示「店员已经开始看你了」，数值不变 |
| 空购物车点「清空」 | 拦下，提示「购物车本来就是空的」 |
| 图片加载失败 | 回退像素图，不影响流程 |
| **缺料** | `KITCHEN → KITCHEN` 标记并划掉一份 → `KITCHEN → PICK` 回退重选，剩余份数保留 |
| 整单被划空 | `KITCHEN → EXIT_EMPTY → REVIEW`，不允许跳过状态直接到结局 |
| 载入非法菜单文件 | 菜单与状态**都不变**，只提示读不出来 |
| 转移执行中抛异常 | 自动回滚状态 + 数值快照（`rollback`），日志标「异常已回滚」 |
| 什么都没点就走 | `CONFIRM → EXIT_EMPTY → REVIEW`，是合法分支不是错误 |

加 `?debug=1` 可以在右下角实时看到 `state / undo / voices / 最近 6 条转移日志`。

### 6 个结局 + 3 个隐藏成就

| # | 结局 | 触发 |
|---|---|---|
| 01 | **合法快乐** | 放纵 × 接纳 —— 你吃得很开心，也没有怪自己 |
| 02 | **深夜 retrospective** | 放纵 × 自责 —— 你在心里给自己开了场复盘会 |
| 03 | **刚刚好的一口** | 中庸 × 接纳 —— 不炫技，不冗余，跑得很稳 |
| 04 | **还行吧，反正能跑** | 中庸 × 自责 —— It compiles. Ship it. |
| 05 | **温柔的克制** | 克制 × 接纳 —— 这叫优雅降级，系统没崩，只是降频运行 |
| 06 | **饿着睡的苦行僧** | 克制 × 自责 —— 你赢了热量，输了睡眠 |
| 🏆 | **全家桶工程师** | 一局点满 4 样（隐藏） |
| 🏆 | **未完成的 commit** | 吃到一口不吃了，把剩下的留在盒子里（隐藏） |
| 🏆 | **404 Not Found** | 遇到餐品卖完了，并且接受了这件事（隐藏） |

**没有失败结局。** 结算页明写：本局没有评分，没有最优解。

## 安装方法

### 方式 A：直接玩（30 秒）

```bash
open game/midnight-snack.html      # macOS
# 或者：双击 game/midnight-snack.html
```

内置了一份 2026-10-22 从**深圳松坪山餐厅**（24h 营业，含「宵夜 00:00–04:45」时段）拉取的真实菜单，
所以不配 MCP 也能玩。

### 方式 B：用你自己门店的数据玩

```bash
# 1. 到 https://open.mcd.cn/mcp 登录，在「控制台」申请 MCP Token
# 2. 生成你城市 / 你门店的菜单
MCP_TOKEN=你的token node scripts/fetch-menu.mjs --city 北京 --keyword 中关村

# 3. 打开游戏
open game/midnight-snack.html
```

生成成功后开始界面会显示 **「★ 当前使用你的门店实时菜单」**。

也可以不重新生成 —— 直接打开游戏，点开始界面的
**「📂 载入我的门店菜单」**，选中 `data/menu.json`（仓库里已附一份深圳松坪山餐厅的真实数据可直接试）。
换门店、换城市都靠这个入口。

## 使用示例

**示例 1 —— 全放纵路线**
选「站起来下楼」→「吃，今天已经够苦了」→ 心情「报复性快乐」→ 巨无霸 + 薯条（再点一份）
→「换大份！」→ 一口一口全部点掉 → 事后说「我今天值得这一顿」→ 睡前「什么都不想了，先睡」
→ **结局：合法快乐**，满足感 +60，焦虑 −58，体重 +0.157 kg。

**示例 2 —— 全克制路线**
选「直接回家」→「不吃，明天还要看体检报告」→ 什么都不点 →「回家，饿着睡」
→ 事后说「完了，明天的体重……」→ 睡前「设闹钟明早跑两公里」
→ **结局：饿着睡的苦行僧**，热量 0，但焦虑 +14、睡眠没了。

**示例 3 —— 中间路线**
只拿一份苹果片 + 纯牛奶，一口一口慢慢吃掉，事后说「我今天值得这一顿」
→ **结局：刚刚好的一口**，热量 +129 kcal，焦虑 −33。

**示例 4 —— 点了很多，吃了一半**
点了 3 份薯条，吃掉第一份就点「放下，不吃了」
→ **解锁「未完成的 commit」**，热量只算吃下去的那部分，接纳度 +8。

三条路线**都不扣分，都给结局**。这就是这个游戏想说的：放纵和克制都不是错误答案。

## 真实使用麦当劳 MCP 的说明

详见 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md)。概要：

| Tool | 用途 |
|---|---|
| `query-nearby-stores` | 选一家真实门店，优先 24h 营业 / 含宵夜时段 |
| `query-meals` | 拿 13 个分类约 90 款在售餐品的**名称、分类、真实售价、官方图片** |
| `query-meal-detail` | 拿**官方配料**（`modification.items[].values[]` 中 `selectedQuantity > 0` 的项）与更高清图片 |
| `list-nutrition-foods` | 拿官方营养表的**真实热量 / 蛋白 / 脂肪 / 碳水 / 钠 / 钙** |

游戏里每个数字都来自官方接口，不是编的。附真实调用 Trace ID 可查。

## 设计原则：刻意不做什么

| 不做 | 原因 |
|---|---|
| 不做分账、不显示人均 | 朋友之间不差那几块钱，算到分是荒谬的 |
| 不惩罚任何选择 | 玩家已经累了一天，不该在游戏里再被审判一次 |
| 不把品牌与「长胖」做归因 | 主题是「疲惫的人需要被照顾」，不是「这食物有害」 |
| 不接广告、不引导下单 | 它是个情绪产品，不是转化漏斗 |
| 不引入构建工具与外部 CDN | 保证三年后双击还能打开 |

## 技术说明

- 单个 HTML 文件，内联 CSS/JS，**零外部依赖、零构建工具**
- 像素图是 12×10 点阵用 CSS Grid 渲染的（不是 emoji，不是图片）
- 进食的「分口」是把点阵按行切成 3–6 段，每段带独立标签与热量权重（权重合计 1）
- 菜单载入用 `<input type="file">` + FileReader，因此 `file://` 下也能用（fetch 会被 CORS 拦）
- 音效是 Web Audio API 现场合成的 8-bit 波形 —— 振荡器 + 增益包络（attack 8 ms + 指数释放），
  经总线压缩、复音上限、按名节流三重保护，右上角可静音 / 调音量
- 全流程由 12 状态 22 转移的显式状态机驱动，带 undo 栈与数值快照回滚
- 结局卡可一键复制到剪贴板，方便分享
- 支持移动端，响应式布局
